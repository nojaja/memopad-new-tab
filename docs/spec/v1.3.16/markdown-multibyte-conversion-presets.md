# v1.3.16 - Markdown マルチバイト変換プリセット機能（Issue #92）設計書

## ドキュメント情報
- バージョン: 1.3.16
- 更新日: 2026-06-04
- ステータス: 設計書
- 分類: Markdown 設定拡張
- 関連Issue: #92 変換機能のプリセットがほしい

---

## 1. 概要

### 1.1 背景
現行の Settings -> Markdown にあるマルチバイト変換ルール（list-group）は、都度同じルールを手作業で編集する必要があり、用途ごとの切り替えに手間がかかる。

Issue #92 では、変換ルール一覧に名前を付けて保存し、必要なときに読み込み・切り替え・削除できるプリセット機能が要求されている。

### 1.2 目的
- マルチバイト変換ルール一覧をプリセットとして保存できるようにする。
- 保存済みプリセットをプルダウンから選択し、現在のルール一覧へ一括適用できるようにする。
- 不要なプリセットを削除できるようにし、設定管理を容易にする。

### 1.3 スコープ
- Settings -> Markdown -> Multibyte セクションにプリセット選択 UI を追加する。
- 「読み込み」「保存」「削除」アクションを追加する。
- localStorage の config にプリセットデータを永続化する。
- 初期値として「プリセット」を登録し、既定の変換ルール一覧を保持する。

### 1.4 非スコープ
- マルチバイト変換処理アルゴリズム自体の変更（正規表現実行順・変換仕様）。
- 他設定セクション（General / Editor）へのプリセット機能展開。
- 外部ファイル入出力によるプリセット共有機能。

---

## 2. ユースケース

### 2.1 プリセットを読み込む
1. ユーザーが「変換を有効化」の下にあるプリセットプルダウンから項目を選択する。
2. 「読み込み」を押下する。
3. 確認ダイアログで了承すると、現在の `multibyteconvertList` が選択プリセットの内容で洗い替えされる。

### 2.2 現在のルールをプリセット保存する
1. ユーザーが `multibyteconvertList` を編集する。
2. 「保存」を押下する。
3. 名前入力を含む確認ダイアログで保存名を確定する。
4. 現在のルール一覧が指定名のプリセットとして保存され、プルダウンから選択可能になる。

### 2.3 不要なプリセットを削除する
1. ユーザーがプルダウンで削除対象プリセットを選択する。
2. 「削除」を押下する。
3. 確認ダイアログで了承すると、対象プリセットが削除される。

### 2.4 初期状態
1. 初回起動またはプリセット未定義の既存設定を読み込む。
2. プルダウンに「プリセット」が存在し、既定の変換ルール一覧を保持している。

## 3. 機能要件

### 3.1 UI要件
- 「変換を有効化」チェックボックス直下に、以下を横並びまたは同一グループで配置する。
  - プリセット選択プルダウン
  - 「読み込み」ボタン
  - 「保存」ボタン
  - 「削除」ボタン
- プルダウン初期選択値は「プリセット」とする。

### 3.2 読み込み要件
- 「読み込み」実行時、確認ダイアログを表示する。
- OK 時のみ、選択プリセットのルール一覧で `localConfig.markdown.multibyteconvertList` を置換する。
- キャンセル時は状態を変更しない。

### 3.3 保存要件
- 「保存」実行時、保存名を入力できるダイアログを表示する。
- 入力名が有効な場合、現在の `multibyteconvertList` を指定名のプリセットとして保存する。
- 同名が存在する場合は上書き確認を行い、OK 時のみ上書きする。
- 保存完了後、保存したプリセットをプルダウン選択状態にする。

### 3.4 削除要件
- 「削除」実行時、確認ダイアログを表示する。
- OK 時のみ、選択プリセットを削除する。
- 「プリセット」（初期プリセット）は削除不可とする。
- 削除後の選択状態は「プリセット」に戻す。

### 3.5 永続化要件
- プリセット一覧は `config.markdown` 配下へ保存し、既存設定と同じ保存タイミングで永続化する。
- 再起動後もプリセット一覧と選択状態が復元される。
- 既存設定（プリセット未保持）を読み込む場合は正規化処理でデフォルトを補完する。

### 3.6 バリデーション要件
- プリセット名は前後空白を trim し、空文字は不可とする。
- 重複名判定は trim 後の値で行う。
- 読み込み・削除実行時に選択値が不正（存在しない）な場合は処理せず警告表示する。

---

## 4. 非機能要件

### 4.1 パフォーマンス
- プリセット読込・保存・削除操作は即時反映できる応答性を維持する。
- 変換処理本体（Preview 更新）に追加の重い処理を持ち込まない。

### 4.2 互換性
- 既存の `multibyteconvert` / `multibyteconvertList` の挙動を保持する。
- 旧バージョン config を読み込んでもアプリ起動時エラーにならない。

### 4.3 保守性
- ダイアログ文言、ボタン文言、エラーメッセージは i18n キーで管理する。
- プリセット操作ロジックは SettingPage 内の独立メソッドに分離し、watcher 連鎖を複雑化しない。

## 5. データ設計

### 5.1 config 拡張案
`config.markdown` に以下を追加する。

```ts
type MultibytePreset = {
  name: string
  rules: Array<[string, string]>
}

type MarkdownConfig = {
  multibyteconvert: boolean
  multibyteconvertList: Array<[string, string]>
  multibytePresetSelected: string
  multibytePresetList: MultibytePreset[]
}
```

### 5.2 初期値
- `multibytePresetSelected`: `"プリセット"`
- `multibytePresetList`: 1件以上
  - `name: "プリセット"`
  - `rules: defaultConfig.markdown.multibyteconvertList` と同値

### 5.3 normalizeConfig 方針
- `multibytePresetSelected` が未定義なら `"プリセット"` を補完。
- `multibytePresetList` が未定義または不正配列なら初期プリセットのみを補完。
- `multibytePresetList` から「プリセット」が欠落している場合は先頭に再挿入。

## 6. インターフェース定義

### 6.1 SettingPage 追加インターフェース（想定）
- `getMultibytePresetOptions(): Array<{ name: string, value: string }>`
- `loadSelectedMultibytePreset(): void`
- `saveCurrentMultibytePreset(): void`
- `deleteSelectedMultibytePreset(): void`

### 6.2 ダイアログ契約
- 読み込み: 確認ダイアログ（OK/Cancel）
- 保存: 入力付きダイアログ（プリセット名） + 必要時上書き確認
- 削除: 確認ダイアログ（OK/Cancel）

注記:
- 既存のダイアログヘルパーがある場合は再利用を優先する。
- 実装時の最終メソッド名は既存命名規約に合わせて確定する。

## 8. 互換性と移行計画

### 8.1 互換性
- 既存ユーザーの `multibyteconvertList` は保持する。
- 旧 config には初期プリセットを補完し、既存の現在ルールはそのまま編集可能にする。

### 8.2 移行
- 既存 config 読み込み時に `normalizeConfig` で新規キーを付与する。
- 初回移行時は `multibytePresetList` に「プリセット」を作成し、rules に既定ルールを設定する。
