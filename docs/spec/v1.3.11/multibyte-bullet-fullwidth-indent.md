# 全角スペース付き「・」変換のインデント対応仕様書

## ドキュメント情報
- バージョン: 1.3.11
- 更新日: 2026-05-22
- ステータス: 設計書
- 分類: 変換機能改善
- 関連Issue: #91 変換で・の変換で全角スペースが入ったらインデントしてほしい

---

## 1. 概要

### 1.1 背景・課題
Settings -> multibyte -> Enable convert の変換設定にある `^(\S*)・` -> `$1- ` は、行頭に全角スペース（`\u3000`）がある場合を想定していない。

そのため、次の入力:

```text
・アイテム1
　・サブアイテム1-1
　・サブアイテム1-2
```

に対し、1行目だけが `- ` に変換され、2行目以降は意図した Markdown ネストリストにならない。

### 1.2 目的
- 行頭の全角スペース数を Markdown リストのインデントに正しく変換する。
- 「・」記法から Markdown 箇条書きへの変換結果を一貫させる。
- 既存の multibyte 変換機能との互換性を維持する。

### 1.3 スコープ
- 行頭に含まれる全角スペース + `・` の変換仕様を追加する。
- 半角スペースとの混在を許容し、インデント深さを決定する。
- 既存の `・` 以外の変換ルールは対象外とする。
- 対応手段は `Settings -> multibyte -> Enable convert` の変換設定内容変更に限定する。
- アプリケーションコード（Vue/TypeScript）のロジック変更は行わない。

---

## 2. ユースケース

### 2.1 単純な箇条書き変換
1. ユーザーが `・アイテム1` を入力する。
2. 変換後に `- アイテム1` になる。

### 2.2 ネスト箇条書き変換（全角スペース）
1. ユーザーが `　・サブアイテム` を入力する。
2. 行頭の全角スペースを1段インデントとして解釈する。
3. 変換後に `  - サブアイテム` になる。

### 2.3 複数段ネスト
1. ユーザーが `　　・第2階層` のように全角スペースを複数入れる。
2. 全角スペース1文字あたり半角スペース2文字へ変換する。
3. 変換後に `    - 第2階層` となり、Markdown の入れ子として解釈される。

---

## 3. 機能要件

### 3.1 変換対象検出要件
- 行頭に空白（全角/半角）を含み、その直後に `・` がある行を変換対象とする。
- 空白なしの `・` 行も従来どおり変換対象とする。

### 3.2 インデント変換要件
- 全角スペース `\u3000` を半角スペース2文字へ正規化する。
- 変換後の先頭は `{正規化した空白}- ` の形式にする。
- 本仕様では「全角スペース1文字 = 半角2文字」を固定ルールとする。

### 3.3 本文保持要件
- `・` の後続テキストは欠落・並び替えなく保持する。
- 行末の既存文字列（句読点、数字、記号）を保持する。

### 3.4 互換要件
- 既存の `^(\S*)・` 系変換の意図（先頭記号を `- ` に置換）は維持する。
- 既存の multibyte 変換 ON/OFF トグル挙動へ影響を与えない。

### 3.5 設定内容変更要件（本対応の必須条件）
- 変更対象は `config.markdown.multibyteconvertList`（Settings 画面の変換設定）とする。
- `src/js/jmd.json` の既定 `RegExpList` に同等内容を反映する。
- 変換は既存実装どおり「上から順に逐次適用」されることを前提に、ルール順序を固定する。

必須ルール差し替え:
1. 既存 `^(\\S*)・` -> `$1- ` を置換し、先頭空白を許容する。
	- 変更後: `^([ 　]*)・` -> `$1- `
2. 箇条書き行の先頭に残る全角スペースを半角2文字へ正規化する。
	- 追加: `^([ 　]*)　([ 　]*- )` -> `$1  $2`

補足:
- 2 のルールは 1 の直後に配置する。
- 2 は 1 回の置換で先頭全角スペースを 1 文字ずつ半角2文字へ正規化するため、同一ルールを連続で複数登録して多段ネストを吸収する。
- 本仕様では実運用上の最大ネストを 5 段とし、ルール 2 を 5 個連続で定義する。

## 4. 非機能要件

### 4.1 パフォーマンス
- 1行ごとの変換計算量は線形時間に収める。
- 既存の入力遅延体感を悪化させない。

### 4.2 安定性
- 全角スペースを含まない既存文書で挙動が変化しない。
- 空行や `・` を含まない行に副作用を与えない。

### 4.3 保守性
- 変換ロジックはインデント正規化と記号置換を分離して可読性を維持する。
- ルール追加時に正規化関数を再利用できる構造にする。

---

## 5. インターフェース定義

### 5.1 入出力契約（論理）
- 入力: 1行文字列
- 出力: 変換後1行文字列

変換アルゴリズム（論理）:
1. 変換設定リストを先頭から順に適用する。
2. `^([ 　]*)・` -> `$1- ` で箇条書き記号を Markdown 記法へ変換する。
3. `^([ 　]*)　([ 　]*- )` -> `$1  $2` を複数回適用し、行頭全角スペースを段階的に正規化する。
4. 条件を満たさない場合は元文字列を返す。

### 5.2 設定データ定義（抜粋）
`multibyteconvertList` の例（順序固定）:

```json
[
	["^([ 　]*)・", "$1- "],
	["^([ 　]*)　([ 　]*- )", "$1  $2"],
	["^([ 　]*)　([ 　]*- )", "$1  $2"],
	["^([ 　]*)　([ 　]*- )", "$1  $2"],
	["^([ 　]*)　([ 　]*- )", "$1  $2"],
	["^([ 　]*)　([ 　]*- )", "$1  $2"]
]
```

### 5.3 エラー・例外
- 不正な Unicode を含む場合も例外を投げず、可能な範囲で文字列処理を継続する。
- 変換不能時は入力行をそのまま返す（フェイルセーフ）。

## 7. 互換性と移行計画

### 7.1 互換性
- データ構造変更なし。
- 既存設定値の移行不要。
- 半角スペースのみの既存入力は従来どおり扱う。

### 7.2 移行
- 新規インストール: 更新済み `RegExpList` を既定値として適用する。
- 既存ユーザー: `multibyteconvertList` をカスタマイズ済みの場合は自動上書きせず、手動でルール追加できるようリリースノートに差分を記載する。
- ストア構造・移行スクリプトは変更しない。

- [ ] `　　・第2階層` が `    - 第2階層` に変換される。
- [ ] 5 段までの全角インデント付き `・` が期待する半角2文字単位インデントへ変換される。
- [ ] `・` の後続テキストが欠落しない。
- [ ] `・` を含まない行は変換されない。
- [ ] multibyte 変換 OFF 時の既存挙動に変化がない。
- [ ] 本対応で Vue/TypeScript コード変更が発生していない。

## 9. テストケース要約

### 9.1 Unit
- 全角スペース0/1/2個 + `・` の変換結果を検証する。
- 全角スペース3/4/5個 + `・` の変換結果を検証する。
- 全角・半角空白混在行で正規化インデントが期待値になることを検証する。
- 非対象行（`・` なし）で入力不変を検証する。
- 末尾文字列保持（日本語、記号、数字）を検証する。
- ルール順序を入れ替えた場合に失敗することを検証し、順序依存を固定化する。

### 9.2 回帰
- 既存の multibyte 変換ルール（本仕様対象外）が破壊されていないこと。
- エディタ入力時の体感遅延に退行がないこと。

## 11. 設計判断メモ

- 本Issueは「変換設定内容の変更で解決する」ことが前提のため、コード改修案は採用しない。
- 既存の逐次置換エンジン（正規表現 + 置換文字列）で実現可能な方式として、段階正規化ルールの複数定義を採用した。
- ルールの最大段数は 5 とし、超過ケースは将来の設定拡張で対応する。
